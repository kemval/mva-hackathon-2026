# Track 1 Methods Report — Variant Prediction

**Team:** Gummietech
**Proband:** PROBAND01 (source VCF: `WGS_EX2312012_HGWCNDSX7.vcf.gz`)
**Date:** 2026-09-01

## Summary

Analysis of the proband's own whole-genome VCF and HPO-coded clinical phenotype identifies a compound-heterozygous candidate in **BUB1B**: a known pathogenic nonsense variant (p.Leu737Ter, ClinVar VCV000533901.9) paired with an extremely rare missense variant (p.Asn1002Lys, a gnomAD singleton) lying in the protein's kinase domain — though that location is reported as a fact about the variant and is explicitly **not** used as ACMG evidence, for reasons given under PM1. Variant 1 classifies as Likely Pathogenic; variant 2 as a VUS. The search space is a literature-defined panel of known MVA and spindle-assembly-checkpoint genes — that panel choice draws deliberately on published MVA genetics — while the variant call itself comes from filtering the proband's own VCF. A phenotype-driven secondary panel search (11 genes) found no additional candidates. Phase (cis/trans) between the two BUB1B variants could not be directly resolved from this proband-only short-read dataset; this limitation, and what it implies about what else could occupy the second allele, is discussed explicitly below rather than assumed away.

Three evidence codes in this report follow current ClinGen Sequence Variant Interpretation (SVI) specifications rather than the 2015 ACMG/AMP paper as it is commonly applied — PM2 on both variants, applied at Supporting, and PM3, which under the SVI recessive point scheme does not reach even Supporting on a single proband of unresolved phase and is therefore not applied at all. One predictor is reported as uninformative against its own calibration. Those choices are set out under ACMG/AMP evidence below and are deliberate, not incidental. All 2,346 PASS variants across both panels were additionally screened with SpliceAI; none reaches the 0.2 threshold.

## Methods

1. **Data**: proband VCF (`WGS_EX2312012_HGWCNDSX7.vcf.gz`, GRCh38, single-sample, GATK/Sentieon Haplotyper-called) and the proband's HPO-coded clinical phenotype (`Challenge_Clinical_Phenotype_1.docx`).
2. **Primary gene panel**: BUB1B, CEP57, TRIP13 (the three established MVA-causing genes) plus CENATAC, SLF2, SMC5 (MVA subtypes 4-6), MAD1L1, BUB1, BUB3 (spindle-assembly-checkpoint-adjacent genes) — 9 genes total, GRCh38 coordinates resolved via Ensembl REST, ±2kb padding.
3. **Region restriction**: `bcftools view -R` against the padded gene-panel BED, using the provided `.tbi` index — avoided processing the full genome-wide VCF (~2M+ raw records).
4. **Annotation**: Ensembl VEP REST API (canonical transcript, HGVS nomenclature, max gnomAD population allele frequency, **max SpliceAI delta score** via VEP's SpliceAI plugin, ClinVar clinical significance where available). One defect in the allele-frequency field was found and corrected post-hoc without changing the candidate set — see the Verification section.
5. **Filtering**: gnomAD max AF < 0.001 AND VEP impact MODERATE or HIGH on the canonical transcript.
6. **Phenotype cross-check**: proband's HPO terms compared against each gene's known phenotype spectrum (see Phenotype correlation below).
7. **Secondary panel**: TP53, DICER1, NF1, PTCH1, HRAS (rhabdomyosarcoma-predisposition syndromes, per Schneider et al., *Translational Andrology and Urology*, PMC7658107, which names TP53/NF1/DICER1/PTCH1-SUFU as the major RMS-predisposition genes and HRAS/Costello syndrome as a related consideration) and CASR, CLDN16, CLDN19, AGXT, SLC34A1, CYP24A1 (nephrocalcinosis-associated genes, per two pediatric nephrocalcinosis genetics reviews — *Clinical Kidney Journal* 15(4):812 and *Pediatric Nephrology*, PMC12852217 — a literature-grounded but deliberately non-exhaustive subset of the ~30-gene commercial panels these reviews describe), run through the identical pipeline, to investigate two HPO features (nephrocalcinosis, parental recurrent miscarriage) not on the standard BUB1B/MVA symptom list.

Full pipeline: `pipeline/vep_annotate.py` (VEP REST annotation) and `pipeline/filter_candidates.py` (the rarity + impact filter of step 5), with the exact end-to-end command sequence for both panels — including the `bcftools` region-restriction step — documented in `pipeline/README.md`. Raw annotated tables (`data-notes/annotated/`) exist locally but are **not** committed to version control — see Reproducibility below.

### ACMG/AMP evidence

**Variant 1 (p.Leu737Ter, stop_gained)**
- **PVS1 (Very Strong)**: null variant (premature stop) in BUB1B, where loss-of-function is the established mechanism for MVA1. The stop is predicted to trigger nonsense-mediated decay, the first branch of the ClinGen SVI PVS1 decision tree. This was checked against the transcript's actual exon structure rather than inferred from the variant's position within the coding sequence: c.2210 lies in exon 17 of 23, and the final exon-exon junction of ENST00000287598 falls at CDS position 2957, placing the premature stop **747 nt upstream** of it — far outside the ~50-55 nt window in which a premature stop escapes NMD. The transcript is therefore expected to be degraded rather than to produce a stable truncated protein. There is also no cryptic-splice rescue that might skip the premature stop: SpliceAI scores this variant 0.03 (acceptor gain) on all 22 BUB1B transcripts, an order of magnitude below the tool's 0.2 high-recall threshold, so PVS1 rests on NMD as claimed and not on an unexamined assumption about splicing. Even absent NMD, per UniProt (O60566, direct query) BubR1's kinase domain spans residues 766-1050 of the 1050-aa protein, so a truncation at residue 737 **removes the entire kinase domain** (confirmed, not inferred).
- **Corroborative (not scored as an evidence code)**: independently classified Pathogenic/Likely pathogenic in ClinVar (VCV000533901.9, 2-star review status, multiple submitters, no conflicts, specifically for "Mosaic variegated aneuploidy syndrome 1" — direct ClinVar/eutils query, not just VEP's `clin_sig` field). This is deliberately *not* counted toward the classification total. PS4 would be the wrong code — it requires case-control prevalence data, which this analysis did not generate — and the code that does formally cover a reputable-source classification, PP5, has been recommended against by ClinGen's Sequence Variant Interpretation working group since 2018 on the grounds that it double-counts evidence already captured by the primary codes. The ClinVar concordance is therefore reported as independent corroboration of the call, not as additional evidence weight.
- **PM2_Supporting — applied, but it is a close call and the closeness is the point.** gnomAD v4: exomes AC=115/1,461,846 (AF 7.87e-5), genomes AC=5/152,174 (AF 3.29e-5), pooled AF 7.43e-5; **filtering allele frequency (faf95, popmax NFE) = 8.40e-5**. Applied at Supporting rather than the 2015 guidelines' default Moderate, per the ClinGen SVI recommendation adopted by most VCEP specifications.

  Earlier versions asserted rarity rather than deriving a threshold. The threshold is the Whiffin/Ware maximum credible population AF, whose recessive form is **maxAF = A x sqrt(P x G / f)** (P = prevalence, G = fraction of cases attributable to this gene, A = maximum single-allele contribution, f = penetrance). Variant 1 does not comfortably clear it:

  | P (prevalence) | G | A | max credible AF | vs. faf95 8.40e-5 |
  |---|---|---|---|---|
  | 1e-6 | 0.5 | 0.10 | 7.07e-5 | **exceeds** |
  | 1e-6 | 0.5 | 0.05 | 3.54e-5 | **exceeds** |
  | 3e-6 | 0.5 | 0.10 | 1.22e-4 | passes |
  | 1e-5 | 0.5 | 0.10 | 2.24e-4 | passes |

  *Why the allelic term sits outside the square root — a reviewer challenged this placement, so the derivation is given rather than the formula asserted.* Under Hardy-Weinberg, the combined frequency of causative alleles in the gene, q_gene, satisfies P x G = q_gene^2 x f, and a single variant contributing fraction A of that gene's causative alleles has q_i = A x q_gene. Substituted, that is the framework's own recessive statement — prevalence = (q_i x 1/A)^2 x 1/G x f, hence **maxAF = sqrt(P) x A x sqrt(G) / sqrt(f)** — which is the form used in the table above and matches the recessive derivation in the Whiffin et al. 2017 manuscript source (`ImperialCardioGenetics/frequencyFilter`, `manuscript/manuscript.Rmd`). The sanity check one naturally reaches for cannot settle this: for a single fully-penetrant variant causing every case of a 1-in-10,000 recessive disease (A = G = f = 1), *both* placements of A return sqrt(1e-4) = 1%, the paper's stated recessive cutoff. The two forms differ by a factor of 1/sqrt(A) and are distinguishable only at A < 1, so it is the derivation, not the worked case, that fixes A outside the root.

  **None of the three inputs is independently sourced, and all three are flagged here rather than only the prevalence.** There is no published prevalence figure for MVA1 — the literature describes it only as ultra-rare, fewer than a hundred reported cases worldwide. Nor was a published figure found for BUB1B's share of MVA cases: BUB1B is the first-identified and most commonly reported of the three established genes (Hanks et al. 2004), but **G = 0.5 is an assumption, not a citation, and A = 0.10 likewise**. The criterion is therefore properly read as a condition over all three: PM2 fails whenever A x sqrt(P x G) < 8.40e-5. Holding f = 1 (biallelic MVA1 is fully penetrant), G = 0.5 and A = 0.10, the conclusion flips at **P ~ 1.4e-6** — below that, variant 1 fails PM2 — but the flip point moves with the other two as well: halving A alone, to 0.05, pushes it to P ~ 5.6e-6. This report applies PM2_Supporting on the judgement that MVA is substantially underascertained — a mosaic aneuploidy phenotype needs a karyotype nobody orders without prior suspicion — but that judgement is not independently sourced either, so the code is contingent on it. It is not load-bearing: variant 1 reaches 8 points on PVS1 alone, Likely Pathogenic without PM2 at all.

**Variant 2 (p.Asn1002Lys, missense)**
- **PM2_Supporting**: a gnomAD singleton — observed in exactly 1 of 1,461,878 gnomAD exome alleles (AF≈6.84e-7), absent from gnomAD genomes, faf95 undefined; direct gnomAD API query. Applied at Supporting per ClinGen SVI rather than the guidelines' default Moderate. Unlike variant 1 this clears the max-credible-AF threshold derived above under every assumption in that table — by a factor of ~50 against the strictest row (3.54e-5) and ~330 against the most permissive, so PM2 here is not contingent. (Correction: VEP's REST proxy reported this as "absent," because Ensembl's bundled gnomAD annotation dataset had not indexed this ultra-rare variant — the direct gnomAD query is the authoritative figure and should be used, not "absent.")
- **PM1 — tested and NOT applied.** An earlier version of this report applied PM1 at Moderate because residue 1002 falls within UniProt's (O60566) kinase-domain annotation, 766-1050. The coordinates are correct, but coordinates are not the criterion: PM1 requires a hot spot and/or a critical, well-established functional domain **without benign variation**, and that clause was never tested. Tested now, the domain fails it:

  | | kinase domain 766-1050 (285 aa) | rest of protein (765 aa) |
  |---|---|---|
  | distinct gnomAD v4 missense | 320 | 953 |
  | per residue | **1.12** | **1.25** |
  | residues carrying ≥1 missense | 199 (69.8%) | 561 (73.3%) |
  | highest missense AF | 1.12e-3 (p.Asn1032His, AC 1806) | — |

  The domain is not depleted of missense variation — it carries 320 distinct missense variants across 69.8% of its residues, at essentially the same density as the rest of the protein (1.12 vs 1.25 per residue, a ~10% difference in the *less*-dense direction — nowhere near the depletion the criterion asks for) — and carries standing variation at AF 1.1e-3 inside it and AF 6.0e-4 (p.Asn1004Ser, AC 974) two residues from the candidate. Gene-level missense constraint is absent (o/e 0.91, mis_z 1.30). It is also a **pseudokinase**: Suijkerbuijk et al. 2010 show the 265-aa kinase domain is dispensable for both mitotic-checkpoint activity and microtubule attachment, so the "active site of an enzyme" archetype PM1 is written around does not transfer.

  One further detail, which must not be read as reviving PM1: the standing variation cited against it includes p.Asn1004Ser (AF 6.0e-4), and structural modelling puts that residue at **RSA 53% — surface-exposed** — while the candidate two residues away is buried at 16.2% (`data-notes/structural_analysis_n1002k.md`). Position within the domain still differs residue by residue. That is an argument against treating the domain as a hotspot, not an argument for treating residue 1002 as one.

  PM1 is dropped rather than re-founded. The alternative footing considered was the disease-specific spectrum — Suijkerbuijk report MVA missense substitutions occurring "in or near" the kinase domain — but that is eight alleles from one 2010 British series, two of which (Y155C, R550Q) fall well outside it, and the paper's body text says "often in the kinase domain", not consistently. ClinVar now lists the in-domain members of that same series (p.Arg814His, p.Gln921His) as **Conflicting classifications of pathogenicity**, while the only BUB1B missense classified Likely pathogenic without conflict (p.Gln467His) lies *outside* the domain. There is no ClinGen VCEP for BUB1B to arbitrate. Re-founding PM1 there would trade a wrong argument for an untested one.

  Independently of PM1, the variant does act by protein change rather than splicing: SpliceAI returns 0.00 on all four delta scores across all 22 BUB1B transcripts. The 0.02 in the `spliceai_max_ds` column comes from two overlapping *PAK6* transcripts, not from BUB1B.
- **PM3 — tested against the ClinGen SVI point scheme, and NOT applied.** Earlier versions applied PM3 at the 2015 default Moderate, for a candidate second hit in trans with a known-pathogenic variant in the same recessive-disease gene. That was inconsistent with this report's own adoption of ClinGen SVI for PM2, and under the SVI's recessive scheme (*SVI Recommendation for* in trans *Criterion (PM3)*, version 1.0) it does not reach Moderate. That document's Table 1 awards points per proband by phase and by the classification of the variant on the other allele, and Table 2 converts the total to a strength — PM3_Supporting 0.5, PM3 1.0, PM3_Strong 2.0, PM3_VeryStrong 4.0:

  | proband | variant on the other allele | phase | points |
  |---|---|---|---|
  | **this one** | **Likely pathogenic** (this report's own classification of variant 1) | **unknown** | **0.25** |
  | — | Pathogenic (ClinVar's tier for variant 1) | unknown | 0.5 |
  | — | Pathogenic | confirmed in trans | 1.0 |

  This is a single proband with **unresolved phase**, and this analysis classifies variant 1 as Likely Pathogenic on its own evidence. That scores 0.25 points — **below the 0.5 floor for even PM3_Supporting** — so PM3 contributes nothing as things stand. It reaches PM3_Supporting only if variant 1 is taken at ClinVar's Pathogenic tier rather than this report's own, and PM3 at Moderate only once phase is confirmed in trans. See "Limitation: phase not directly resolvable" below.
- **PP3 (Supporting, weak)**: direct dbNSFP query (via MyVariant.info, `chr15:g.40220612T>G`) returns AlphaMissense (0.92/0.88, "likely pathogenic"), CADD phred 24.5, PolyPhen-2 (1.0/0.997, "probably damaging"), and SIFT (0.0, "deleterious") all concordant for damaging — but REVEL, the meta-predictor ClinGen's SVI group recommends over simple tool-counting, scores 0.472. Against the SVI's own calibrated thresholds (Pejaver et al. 2022, the same work that grounds the recommendation to use a single calibrated predictor rather than counting tools), PP3_Supporting requires REVEL ≥0.644 and BP4_Supporting requires ≤0.290 — so 0.472 sits in the **indeterminate band**, supporting neither pathogenicity nor benignity. Strictly applied, that calibration would yield no PP3 at all from REVEL. PP3 is therefore invoked only as weak/supporting on the strength of the concordant tools, with the explicit caveat that the best-calibrated single predictor is uninformative here — reported rather than resolved by picking the tools that agree.

**Combined classification, stated first:**

- **Variant 1 (p.Leu737Ter) is Likely Pathogenic on its own**, before any corroborative ClinVar evidence is counted.
- **Variant 2 (p.Asn1002Lys) is a VUS in isolation**, pending phase confirmation.
- **The pair is diagnostic if — and only if — the two variants are in trans.**

The compound-heterozygous call therefore rests on variant 1's independent classification, the phenotype match (PP4), and the trans argument in the Limitation section below. It does not rest on variant 2 classifying independently; reporting it the other way round would let the unresolved phase quietly score itself.

*Scoring detail.* Codes are combined with ClinGen's Bayesian points framework (Tavtigian et al. 2018) rather than the 2015 combining table, for internal consistency: PM2_Supporting is a ClinGen SVI recommendation, so the ClinGen combining rules are the ones that go with it. Variant 1: PVS1 (8) + PM2_Supporting (1) = 9 points → Likely Pathogenic. Variant 2: PM2_Supporting (1) + PP3 weak (1) = **2 points — a VUS**, PM3 contributing nothing at 0.25 SVI points (above). Withhold the weak PP3 as well (see the REVEL calibration note) and it is 1. Successive versions of this report scored variant 2 at 6 points by including PM1 at Moderate, then at 4 by retaining PM3 at the 2015 default Moderate; with PM1 dropped and PM3 scored under the specification this report says it follows, **no code combination reachable by this analysis lifts variant 2 out of VUS**. The ceiling — reached only if parental testing confirms trans *and* variant 1 is taken at ClinVar's Pathogenic tier — is PM2_Supporting (1) + PM3 (2) + PP3 weak (1) = 4 points, still VUS. That is stated plainly because it changes what the recommended confirmatory test delivers, and the recommendation below is corrected to match. *Which specification applies where:* ClinGen SVI is used throughout — PM2 at Supporting, PM3 on the recessive point scheme, and the Tavtigian points framework for combining — rather than SVI where it happens to lower a code and the 2015 defaults where it would not. That consistency is what moved PM3; adopting SVI for PM2 alone would have been the selective reading this report criticises elsewhere. One consequence of the conservative code choices is worth naming: under the strict 2015 combining table, PVS1 plus a single *Supporting* code would not formally reach Likely Pathogenic (that table wants 1 Very Strong + 1 Moderate), so variant 1's classification rests on the points framework rather than on PM2 retained at Moderate. Either route gives the same answer — with PM2 at Moderate the 2015 table reaches Likely Pathogenic directly — but the route is stated rather than glossed.

### Phenotype correlation (PP4)

The proband's HPO-coded features — rhabdomyosarcoma (HP:0002859), short stature (HP:0004322), failure to thrive (HP:0001508), skeletal muscle atrophy (HP:0003202), premature birth (HP:0001622), and very-low-birth-weight/IUGR (HP:0001518) — match the BUB1B-MVA (MVA1) phenotype spectrum closely, including the specific association with embryonal rhabdomyosarcoma reported in the original BUB1B-MVA discovery cohort (Hanks et al. 2004). The reference spectrum used for this comparison is the MVA1 clinical synopsis of OMIM 257300 / Orphanet 1052, not an informal impression: growth restriction of prenatal onset, microcephaly, and childhood cancer predisposition are its core features.

**One of those three core features is absent from the proband's coded phenotype, and earlier versions of this report did not say so.** Microcephaly carries no HPO term in the eight-term list supplied. That asymmetry is worth naming directly: this report scrutinised the two features lying *outside* the MVA1 spectrum at length while passing over a core feature *inside* it that does not appear. Absence of an HPO code is not absence of the finding — the supplied list is explicitly the set of features that "led to whole genome sequencing," not a complete examination record, and occipitofrontal circumference is routinely measured but not always coded — so this is a gap in the input, not a documented negative. It does mean PP4 is being applied against a partial match rather than a complete one, and the head circumference is a specific thing to ask the clinical team for.

**PP4 strength.** PP4 is invoked in this report but is deliberately **not** scored into either variant's points total, and it appears in neither arithmetic above. That is a choice rather than an oversight, and the reason is that PP4 as written covers a phenotype highly specific to a single gene with a corresponding aetiology; the MVA1 features present here — prenatal growth restriction, failure to thrive, childhood cancer predisposition — are individually non-specific, the discriminating one (mosaic aneuploidy on karyotype) has not been assayed in this proband — a gap now carried through into the recommended confirmatory tests below, where that karyotype leads rather than being merely noted as missing — and one core feature is uncoded. Scored formally it would be PP4_Supporting at most, worth 1 point, which would move variant 1 from 9 to 10 (Pathogenic rather than Likely Pathogenic under the points framework) — a reclassification this evidence does not warrant. It is therefore carried **qualitatively**: it supports the gene-level conclusion and the EPCR, and contributes nothing to either variant's ACMG classification. Where this report says the compound-heterozygous call "rests partly on PP4," that is what is meant.

The differential against the other two classical MVA genes is settled **at the variant level, before phenotype is considered**: the proband carries no rare damaging variant in either CEP57 or TRIP13. The nine-gene screen returned just seven variants across the two genes (four CEP57, three TRIP13), every one of them intronic MODIFIER and common in gnomAD (AF 0.017-0.998); none comes close to the rare-and-damaging filter. That, and not the tumour type, is what excludes these two genes in this proband.

The phenotype is concordant with that conclusion, but it discriminates less sharply than an earlier draft of this report claimed, and the difference is worth stating precisely:

- **BUB1B-related MVA1 (OMIM 257300)** is the subtype in which embryonal rhabdomyosarcoma is specifically reported — including in the original discovery cohort, whose abstract describes five MVA families "including two with embryonal rhabdomyosarcoma" (Hanks et al. 2004, PMID 15475955).
- **TRIP13-related MVA3 (OMIM 617598)** is characterised by early-onset Wilms tumour, present in most affected individuals (Yost et al. 2017) — a different tumour from the one observed here.
- **CEP57-related MVA2 (OMIM 614114)** presents with prenatal-onset growth retardation, distinctive facial features, and skeletal, endocrine and cardiovascular abnormalities. Malignancy is not reported in the published human cases — 11 families as of Kaur et al. 2023 (*Am J Med Genet A*, PMID 36635612: "Only 11 families and 5 pathogenic variants of MVA2 have been described so far"), with a 2026 case report putting the patient count at 16 — but this report explicitly **declines to treat that absence as discriminating**. Cep57 is an established haploinsufficient tumour suppressor: heterozygous mice show elevated tumour incidence (65% vs 24% at 16 months) with tumours retaining Cep57 expression, and the authors write that the data "warrant future investigations as to whether homozygous and heterozygous carriers of inactivating CEP57 mutations would benefit from intensified cancer screenings" (Aziz et al., *JCI* 2018, 10.1172/JCI120316 — an open-access paper captured in this project's own `literature/`). An earlier version of this report rendered that as the authors *recommending* surveillance, which is stronger than what they wrote. Absence of reported cancer across a handful of families is weak evidence of absence, and weighing it against a source in our own repository that argues the opposite would be selective reading.

So the proband's rhabdomyosarcoma is positively concordant with MVA1 and points away from MVA3's Wilms-tumour profile; the stronger claim — that it rules out CEP57 — is withdrawn. PP4 rests on the overall MVA1 phenotype match (prenatal-onset growth restriction, failure to thrive, childhood cancer predisposition).

An earlier version of this report replaced the withdrawn tumour-type argument with the claim that "CEP57 and TRIP13 are excluded by the variant-level screen," describing that as the stronger, previously unstated exclusion. That substitution was not tested and is now qualified. The screen returned no rare damaging variant in either gene, which is true and is what it says. But its **sensitivity in these two genes was never established**, and measuring it shows the two genes are not equivalent:

| gene | region | PASS calls | calls/kb | flanking calls/kb | depth of the calls present |
|---|---|---|---|---|---|
| CEP57 | 47.1 kb | 4 | 0.08 | 0.46 | DP 35-52 |
| TRIP13 | 26.5 kb | 3 | 0.11 | 0.09 | DP 7, 7, 48 |

CEP57 yields **5.4x fewer calls than its own flanking sequence**, on four calls total. That is too few observations to distinguish a low-diversity haplotype from a region the caller could not interrogate, and in a sites-only VCF absence of a call and absence of coverage are indistinguishable. TRIP13 is quiet, but so is its neighbourhood — the density matches its flanks — so its negative is better supported than CEP57's, though it rests on three calls of which two are at DP 7.

The defensible statement is therefore: **the variant-level screen found no rare damaging variant in CEP57 or TRIP13, and the screen's sensitivity in CEP57 in particular is unestablished.** That is weaker than what this report previously claimed. It is not compensated for by restoring the tumour-type argument, which was withdrawn for good reason and stays withdrawn. Settling it would take the coverage track (gVCF or BAM/CRAM), which this analysis does not have.

## Secondary finding: a candidate alternative second allele, tested and downgraded

chr15:40216470 A>G (c.2679-1026A>G), deep intronic, absent from gnomAD (independently re-confirmed via direct gnomAD v4 GraphQL query, not just VEP's proxy — the query returns "Variant not found," genuinely absent, not an under-indexing artifact like the p.Asn1002Lys correction above), physically located between the two primary candidates within BUB1B.

**Why it was worth taking seriously.** BUB1B-MVA is recessive, variant 1 is a confirmed null, and the proband is affected — so something must disrupt the second copy. The primary hypothesis is that p.Asn1002Lys does. Were p.Asn1002Lys instead in *cis* with the nonsense variant, a rare, gnomAD-absent, deep-intronic variant in the same gene would become the obvious next candidate, acting through cryptic splice-site or pseudoexon activation — precisely the mechanism a MODERATE/HIGH impact filter is built to discard. That made it a hypothesis worth testing rather than an incidental curiosity to be listed and left.

**It was tested, and the result is negative.** SpliceAI returns **0.00 for all four delta scores** — acceptor gain, acceptor loss, donor gain, donor loss — on all 22 BUB1B transcripts. Against SpliceAI's own published thresholds (0.2 high-recall, 0.5 recommended, 0.8 high-precision — Jaganathan et al. 2019 and the tool's documentation) this is as clean a negative as the tool produces. The pseudoexon-activation hypothesis is not supported. The variant is therefore reported as an incidental finding at EPCR 0.10, not as a competing causal hypothesis.

The scores came from **Ensembl VEP's SpliceAI plugin**, not from a separate service, and that matters procedurally. The Broad's standalone SpliceAI Lookup API was unreachable on three separate attempts (connection timeout, HTTP 000 after 45s), and dbNSFP via MyVariant.info returns 404 for deep-intronic positions. But VEP REST — the endpoint this pipeline already calls for every variant — serves the same scores behind a single `&SpliceAI=1` parameter. An earlier draft of this report treated the outage as making the question unanswerable. It did not; the analysis had simply not asked the tool it was already using.

One caveat, kept deliberately narrow: SpliceAI is the best available splice predictor but is imperfect for deep-intronic pseudoexons specifically, and a negative prediction does not carry the weight of a functional assay (RNA-seq or a minigene splicing construct would). It is enough to move this variant out of contention as the second allele. It is not enough to call it benign.

## The two features outside the core MVA1 spectrum

Two HPO-coded features — **nephrocalcinosis (HP:0000121)** and **parental recurrent spontaneous abortion (HP:0200067)** — do not appear in the MVA1 clinical synopsis. An 11-gene secondary panel targeting rhabdomyosarcoma-predisposition and nephrocalcinosis-associated genes (TP53, DICER1, NF1, PTCH1, HRAS, CASR, CLDN16, CLDN19, AGXT, SLC34A1, CYP24A1 — see Methods for the literature grounding of each half) returned no rare, damaging candidates. That panel is a deliberately non-exhaustive subset: real pediatric nephrocalcinosis panels run to roughly 30 genes and this analysis did not run all of them, so a clean result narrows rather than eliminates a monogenic explanation.

But a negative gene panel is the *second* question for both features, and the first question is clinical.

**Nephrocalcinosis — this analysis got this wrong twice, in opposite directions, and both corrections are shown.** Earlier versions of this report offered two acquired explanations "each sufficient on its own": prematurity (loop diuretics, the calcium and phosphate load of parenteral nutrition, immature tubular handling — the proband is coded for both HP:0001622 and HP:0001518), and rhabdomyosarcoma chemotherapy nephrotoxicity (ifosfamide proximal tubulopathy, platinum agents). It concluded that the negative renal panel was "consistent with the most probable explanation rather than a puzzle left over by it," and that a second monogenic renal diagnosis was "the low-prior hypothesis here." One of those acquired mechanisms is itself contested and was stated too flatly: the furosemide association rests on an adjusted OR of 1.26 (95% CI 1.02–1.57) in a single VLBW case-control, against a 32-study systematic review finding "no evidence that furosemide exposure increases the risk," self-graded low strength (`literature/31_...`, matrix C14). Loop diuretics may be named as *a* plausible contributor, never as *the* mechanism.

**The first of those conclusions is withdrawn.** The phenotype document states, in the same table row as the HP:0000121 this report cites, that the nephrocalcinosis is *"present since birth."* Both proposed mechanisms are necessarily postnatal — NICU nephrocalcinosis develops over weeks of care, and the rhabdomyosarcoma is described as the event that triggered urgent investigation years later. Neither could explain a finding genuinely present at birth, so "each sufficient on its own" was an overstatement. The datum was in the input file this analysis was reading, in the row it was reading, and it was passed over.

**That correction then went one step too far, and the step is identifiable.** Withdrawing "each sufficient on its own" was right. Concluding that the genetic prior therefore *rises* does not follow, and the paediatric evidence runs the other way. In a stratified series of 464 children with nephrocalcinosis (Kim et al. 2023, `literature/31_preterm_nephrocalcinosis.md`), the monogenic yield was **~10-fold higher in full-term children** (OR 10.02, 95% CI 2.464–40.786, p = 0.001), and the authors recommend pursuing monogenic causes "especially in full-term patients **without known clinical risk factors**." This proband is preterm (HP:0001622) **with** known clinical risk factors — the profile associated with the *lower* yield.

The premise is also weaker than this report treated it. *"Present since birth"* is one cell in a 2,750-character phenotype summary table written for a hackathon, not a clinical record, and it carries **no imaging date**. Preterm infants are not scanned at birth in any protocol in this literature: first scan at 1 month (Narendra 2001), diagnosis at 35 weeks corrected gestational age (Gilbert 2022), mean age at first diagnosis 385 days (Kim 2023). A summary clause is more likely to compress "identified in the neonatal period" than to date an observation to day 0.

**What this report can honestly say is that it does not know.** If the finding truly were antenatal, the acquired mechanisms could not explain it and the monogenic prior would rise. The datum that would settle it is the date of the first renal ultrasound, which is not in any available file and which this analysis may not request — recontact with the family or clinical team is prohibited. Both readings therefore stay live and neither is allowed to carry a conclusion.

The 6-gene renal subset run here is a **non-exhaustive negative** regardless of how that resolves — six genes against the ~30-gene panels the cited paediatric reviews describe, chosen for their association with the phenotype rather than for coverage of it. Running the full panel remains reasonable; in a preterm child with risk factors it is simply lower-yield than it would be in a full-term child without them.

Two further limits on that negative, both newly identified: (i) CASR — one of the six — carries four MQ40-filtered variant records at 3:122,291,128-122,291,357 that the PASS filter discards without inspection (see Non-PASS records below), so this gene is not cleanly screened; and (ii) the negative rests on absence of calls in a sites-only VCF with callability unmeasured (see Callability). Completing this properly would take the full ~30-gene panel run through the same pipeline, inspection of the filtered CASR records, and the clinical biochemistry (serum and urine calcium, phosphate, magnesium, oxalate, PTH, 1,25-vitamin D) that this analysis has no access to — which is indicated on its own merits in any child with nephrocalcinosis, and does not depend on how the onset question resolves. No acquired mechanism is asserted as *the* explanation here, because the evidence does not support singling one out.

**Parental recurrent miscarriage.** This is better read as *concordant with* the recessive hypothesis than as unexplained by it. Parents of a child with biallelic BUB1B loss are obligate carriers, so one conception in four is affected. If constitutional aneuploidy on the scale MVA produces carries high embryonic lethality — a general expectation asserted here from background knowledge, not a figure this analysis sourced or verified — then recurrent loss is closer to a prediction of the diagnosis than a competing finding. That conditional is doing the work, and it is stated as a conditional deliberately. It is not offered as formal PP4 weight, since the count and timing of the losses are not available and no segregation data exists to test the inference against. The standard competing differential deserves naming: a balanced structural rearrangement in one parent is a leading cause of recurrent pregnancy loss, would be entirely invisible to proband-only SNV analysis, and would be detected by the parental karyotype or microarray that recurrent loss ordinarily prompts.

Neither feature, then, is left as a bare open question — one has a probable acquired cause the genetic analysis was never the right instrument for, and the other is predicted rather than contradicted by the primary hypothesis.

## Limitations of scope: what this design cannot see

Two distinct limits apply, and only the first is a matter of gene choice.

**Gene scope.** A fully unbiased genome-wide rare-variant scan, beyond the 9-gene primary and 11-gene secondary panels, was not performed at full annotation depth in this pass, owing to practical constraints on REST-API-based genome-wide annotation. The panels were chosen to be phenotype-driven and biologically motivated rather than exhaustive. A causal variant in a gene on neither panel would not have been seen.

**Variant-class scope — the more consequential limit, and the one that bears directly on the phase question.** The input is a single-sample GATK/Sentieon Haplotyper SNV/indel VCF, restricted to gene bodies with ±2 kb padding and filtered to MODERATE or HIGH impact on the canonical transcript. That design is structurally blind to:

- **Copy-number variants and exon-level deletions.** Haplotyper does not call them at all. A multi-exon or whole-gene BUB1B deletion is a classic second allele in recessive disease and would be invisible here; detecting it needs read-depth CNV calling on the BAM/CRAM, or an orthogonal assay such as MLPA or microarray.
- **Structural variants** — inversions, balanced and unbalanced rearrangements, retrotransposon insertions — for the same reason.
- **Deep-intronic and pseudoexon-activating variants** are MODIFIER impact and so are excluded by the *candidate filter* as designed — but they are no longer unexamined by the *analysis*. Every PASS variant in both panels was put through SpliceAI, and 1,754 of 2,346 come back with a score (see the screen below), so this class is screened and negative rather than invisible — with the coverage gap stated there rather than papered over.
- **Promoter, enhancer, and other regulatory variants** beyond the 2 kb pad.
- **Effects on non-canonical transcripts**, since VEP *impact* is read from the canonical transcript only. The SpliceAI column is the exception: it takes the maximum across every transcript at the position, including transcripts of neighbouring genes — which is why p.Asn1002Lys is recorded at 0.02, from two overlapping *PAK6* transcripts, rather than the 0.00 every BUB1B transcript returns. Splice effects are therefore assessed transcript-wide; consequence and impact are not.
- **Repeat expansions and mitochondrial variants**, neither assessed.
- **Callability — the limitation under every negative result in this report.** The input is a sites-only VCF: it records positions where a variant was called, and says nothing about positions where none was. Absence of a call and absence of coverage are therefore indistinguishable, and *every* negative here — the secondary panel, the CEP57/TRIP13 screen, the panel-wide splice screen, the absence of a second coding candidate in BUB1B — rests on that undifferentiated absence. No coverage track (gVCF, BAM/CRAM, or callable-region BED) was available or requested. As a partial proxy, call density inside each gene was compared against flanking windows of equal size:

Note also that the two homozygous-alternate calls inside the exon 9-16 window (40193435 at DP 42, 40198239 at DP 36) are formally consistent with hemizygosity, though their entirely normal depth argues against it.

The published allelic architecture bears on the prior here, and cuts against the deletion hypothesis. Suijkerbuijk et al. 2010 report that in biallelic BUB1B-MVA "a missense mutation pairs with a truncating mutation," and their intro records four families in which "a truncating mutation was combined with one amino acid substitution." Their mechanism explains why: truncating alleles yield no transcript, so a residual pool of unstable missense protein is what remains, and it is that reduced-but-nonzero BUBR1 that the patients live on. A multi-exon deletion in trans with p.Leu737Ter would be a truncating/truncating genotype. **The claim made here is the narrow one: across the four biallelic families of that 2010 series, each pairs a truncating allele with a missense one.** An earlier version stated the universal — that no published biallelic MVA1 patient has two truncating alleles — in bold, and then hedged it to four families in the very next sentence. The hedge was the defensible claim, and it is now the only one made: four families from a single series is too narrow a base to establish a universal, and while a search of the biallelic BUB1B/MVA literature turned up no counterexample, one reported PCS/MVA infant's homozygous substitution could not be resolved to missense or truncating from the available abstract. So this lowers the prior on the deletion alternative relative to the compound-heterozygous interpretation, modestly. It would be falsified by a single reported biallelic-truncating MVA1 patient, or by a CNV assay finding a deletion here.

## Limitation: phase not directly resolvable

The two primary BUB1B candidate variants are ~11kb apart. GATK/Sentieon's local read-based phasing (`PGT`/`PID` FORMAT tags) found no phase-informative reads connecting either variant to any nearby heterozygous site — expected, since standard short-read paired-end fragments (typically 300-500bp) cannot physically span an 11kb gap. This is a limitation of proband-only short-read sequencing at this variant separation, not a tooling gap: read-backed phasing tools (e.g. WhatsHap) operating on the same underlying reads would face the identical physical constraint. No parental samples are available for segregation-based phasing. The compound-heterozygous interpretation is therefore **presumed, not directly confirmed.**

The argument for trans is clinical rather than probabilistic, and worth stating in the right order. MVA1 is recessive; variant 1 is a confirmed null allele; the proband is affected. It follows that the second copy of BUB1B must also be disrupted — that inference does not depend on which variant does the disrupting. The open question is therefore not *whether* there is a second hit but *what it is*, and this analysis offers two candidates: p.Asn1002Lys in trans (the primary hypothesis, supported by its rarity — a gnomAD singleton at AC=1 of 1,461,878 — by the recessive requirement that *something* disrupt the second copy, and by the truncating-plus-missense allelic architecture reported for published biallelic BUB1B-MVA; **deliberately not** by its kinase-domain location or by the count of concordant predictors, both of which this report withdraws as evidence under PM1 and PP3 respectively), or — if p.Asn1002Lys proves to be in cis — a variant class this pipeline cannot see, principally a CNV or structural variant in BUB1B (see Limitations of scope). The deep-intronic variant reported above was the third possibility; SpliceAI scores it 0.00 across all transcripts, which substantially weakens it and narrows rather than widens the remaining uncertainty. Framed this way the unresolved phase is not a threat to the diagnosis of BUB1B-MVA, which rests on variant 1 plus PP4; it is uncertainty about which specific second allele completes it.

**Recommended confirmatory tests, in priority order.** An earlier version of this report named only the phase test, having already identified — in the PP4 discussion above — that the feature which actually discriminates MVA has never been assayed in this proband. Naming that gap and then not closing it was the wrong order of business, and the recommendation is corrected to lead with the diagnosis rather than the phase.

**1. Peripheral-blood karyotype, with SNP microarray alongside — the test that diagnoses the condition.** MVA is defined cytogenetically, not molecularly: mosaic aneuploidy — predominantly trisomies and monosomies — involving multiple different chromosomes, conventionally in more than a quarter of cells (OMIM 257300; the diagnostic criteria are chromosome analysis and FISH). Scoring a sufficient number of metaphases from cultured lymphocytes is inexpensive, is available in any cytogenetics laboratory, and would be the standard order for a clinical service presented with this genotype. It bears on the diagnosis in both directions, and both are worth stating: a positive result independently establishes MVA and would lift PP4 from the partial, non-specific match described above to a discriminating one; a **negative substantially undercuts the diagnosis**, and would do so in a way that no further variant-level evidence repairs — every other open question in this report is downstream of a diagnosis this assay has not yet confirmed. The microarray run alongside it also interrogates the five permissive multi-exon-deletion windows left live above, so it addresses the leading alternative second-allele hypothesis at the same time. Note that a normal blood karyotype does not fully exclude MVA, whose aneuploidies are variegated across tissues.

**2. Targeted Sanger sequencing of both variants in both parents — the test that resolves phase.** If each parent carries one variant, phase is established. Under the SVI scheme that lifts PM3 from 0.25 points to 1.0 (PM3 at Moderate) if variant 1 is taken at ClinVar's Pathogenic tier, or 0.5 (PM3_Supporting) at this report's own Likely Pathogenic tier — so **variant 2 remains a VUS either way**, at 4 points at best (see Scoring detail). What the test delivers is therefore not a reclassification of variant 2: it is confirmation that the two variants sit on opposite alleles, which closes out the alternative second-allele hypotheses and secures the *compound-heterozygous genotype*. The diagnosis itself already rests on variant 1 plus PP4 and does not wait on this result. Moving variant 2 out of VUS would take evidence this test cannot supply — functional data on BUBR1 abundance for p.Asn1002Lys (the assay Suijkerbuijk et al. applied to the published MVA alleles), or independent unrelated probands with the same genotype. If both variants prove to be maternal or both paternal, the primary hypothesis is refuted and a CNV/structural-variant assay across BUB1B — MLPA, microarray, or read-depth calling on the BAM/CRAM — becomes the immediate next step, the deep-intronic variant having already been largely excluded on the splice evidence.

**3. Long-read sequencing of the proband** resolves phase directly and is the alternative where parental samples cannot be obtained. All three are concrete, currently available assays rather than a generic wish for more data.

## Submitted predictions and EPCR calibration

The submission CSV contains two rows. Row 1 is the BUB1B compound-heterozygous pair at **EPCR 0.95**; row 2 is the deep-intronic variant at **EPCR 0.10**, flagged `secondary`.

The 0.95 reflects confidence that *this gene and this pair account for the proband's condition*, which is a different question from the formal ACMG classification of either variant taken alone. It is high because variant 1 is independently Likely Pathogenic, is ClinVar-classified specifically for MVA1, and sits in a recessive gene whose phenotype the proband matches — the residual uncertainty is about which second allele completes the genotype, not about whether BUB1B is the cause. It is not 0.99 because phase is unconfirmed and a cis configuration would displace variant 2 from the pair.

**Does 0.95 survive this revision?** The revision above dropped PM1, moved variant 2 permanently into VUS, weakened the CEP57 negative, inverted the nephrocalcinosis reasoning, and disclosed a microcephaly gap and a callability gap. Each was checked against the EPCR rather than assumed to move it:

- *Downgrading variant 2 does not lower the causal probability.* PM1 was never evidence about phase or about causation; it was a claim about a protein domain. The Bayesian case for the pair — an ultra-rare (AC=1) missense in the same recessive gene as a confirmed pathogenic null, in a proband matching the phenotype, with a low prior on two independent rare BUB1B hits — used none of it. ACMG classification and causal probability are different questions, which is the reason this section exists.
- *Variant 1 is unaffected.* PVS1 alone is 8 points, Likely Pathogenic, so even the contingent PM2 above is not load-bearing. The ClinVar MVA1-specific call is untouched.
- *Two things push down.* The microcephaly gap makes PP4 a partial rather than complete match, and the callability finding means "nothing else in these genes" is a weaker negative than presented.
- *One thing pushes up.* The CNV alternative is now partially bounded (eight het calls, no depth loss, whole-gene deletion excluded) and architecturally disfavoured — each of the four biallelic families in the 2010 series pairs a truncating allele with a missense one. That was available in this project's own bibliography from the start and went unused. On a four-family base it pushes up less than an earlier version of this report implied.

These roughly offset, and none is large. **The value stays at 0.95**, which is the same number for better-stated reasons rather than a number defended.

**And does it survive the pass after that?** That pass dropped PM3 to nothing under the SVI point scheme, promoted the karyotype to the first recommended test, cut the allelic-architecture claim back to its four-family base, and corrected an NF1 record count. Only one of those bears on the causal probability. Dropping PM3 does not: exactly as with PM1 before it, PM3 is a claim about how much formal evidence variant 2 carries, not about whether BUB1B causes this child's condition, and the Bayesian case for the pair never used it. The architecture hedge does push down slightly, having been one of the two things pushing up. The karyotype changes nothing *now*, since it has not been run — what it changes is the character of the remaining uncertainty, which is now dominated by a cheap test nobody has ordered rather than by an inference this analysis could have drawn better. **0.95 holds.** The panel view that it sits at the optimistic edge is accepted: the residual 5% has to cover a cis configuration, the five permissive deletion windows, and the regulatory and non-canonical classes this design cannot see.

What would actually move it, in rough order of how decisively: a **karyotype negative for mosaic aneuploidy**, which would undercut the diagnosis itself rather than merely the pairing, and which is the one outstanding test whose result this analysis cannot anticipate at all; a CNV assay finding a deletion in one of the five permissive windows; or parental testing showing both variants on one allele. Each of those drops it sharply. Parental testing confirming trans would take it to ~0.98; a karyotype positive for variegated aneuploidy would do the same by a different route, by converting PP4 from a partial phenotype match into a diagnosis.

The 0.10 on row 2 reflects a variant that was plausible on rarity, gene, and position, and whose one decisive piece of evidence — a splice prediction — was obtained and came back negative (SpliceAI 0.00 across all four delta scores). It started this analysis at 0.30, when that evidence was still missing; the value moved because the evidence arrived, not because secondary rows have a conventional slot. It is not dropped altogether for two reasons: per the hackathon's stated scoring, secondary rows cannot damage the automated result, and a candidate that was raised, tested, and downgraded is part of the reasoning a reader should be able to see, not something to tidy away once it fails.

## Reproducibility

Annotation and filtering scripts (`pipeline/`) and gene-panel coordinate lookups (`data-notes/regions/`) are in the project repository. Every step is parameterised by CLI argument, so no file needs editing to run this in another environment, and `pipeline/README.md` records the exact end-to-end command sequence actually used for both panels — Ensembl REST coordinate lookup → padded BED → `bcftools view -R` → `vep_annotate.py` (which applies the PASS filter) → `filter_candidates.py`. Running `filter_candidates.py` against the annotation output reproduces the reported candidate list exactly (2 rows for the primary panel, 0 for the secondary), so the step from ~1,300 annotated variants down to the submitted candidates is executable code rather than a described procedure. The deep-intronic secondary row is MODIFIER impact and so does not pass that filter by design; the command that surfaces it — the same script with `--impacts MODIFIER` — is documented in `pipeline/README.md` too, so every row in the submitted CSV traces to a runnable command rather than to manual inspection. Per the hackathon's Data Transfer Agreement ("I will not release or otherwise grant data access to anyone"), the raw VCF, phenotype document, and full-panel genotype-level annotation output are intentionally **not** committed to version control — see `data-notes/README.md` for the exclusion policy. Reproducing this analysis requires obtaining independent authorized access to the dataset and re-running the scripts against a freshly downloaded VCF.
